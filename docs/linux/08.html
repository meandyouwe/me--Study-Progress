8. 进程：概念、状态与管理

进程是「运行中的程序」。这句话的重点在「运行中」：程序是磁盘上的静态文件，进程是内存里带着寄存器、栈、页表和一堆内核记账信息的活动实体。

（一）程序、进程、线程

概念存放位置是否占 CPU是否独立地址空间一句话
代码（源文件）磁盘否—文本文件，人写的
程序（可执行文件）磁盘否—编译产物，机器码
进程内存是（被调度）是程序的一次执行
线程内存是（被调度）否（共享进程空间）进程内的执行流

「12+256 GB」指的是 12 GB 内存 + 256 GB 存储，这是手机语境；PC 上是「16 GB 内存条 + 512 GB 磁盘」。进程占的是内存，程序占的是磁盘——这个区分决定了「为什么开 100 个浏览器标签会卡」。

（二）进程的资源空间

每个进程都有独立的虚拟地址空间，布局与 C 语言的五大区一一对应：

扩展 · 虚拟地址的意义：每个进程都以为自己独占 4 GB（32 位）或 2^47 字节（64 位）空间，由 MMU + 页表映射到物理内存。这样进程之间天然隔离——A 进程写越界不会改到 B 进程的数据，只会触发 SIGSEGV。这也是教材说「父子进程各自拥有独立空间」的底层原因。

（三）进程的三个状态与扩展五态

教材给的是最基础的三态模型：

状态含义触发转换
执行态（Running）正占用 CPU时间片用完 → 就绪；等待 I/O → 阻塞
就绪态（Ready）万事俱备，只差 CPU被调度 → 执行
等待态（Blocked）等 I/O 或事件事件到达 → 就绪

工程上更常用五态模型，多出的两个是新建（fork 完成但未就绪）与终止（已退出但未被回收，即僵尸）。ps -aux 的 STAT 列能看到更细的标记：

标记含义
R运行或可运行
S可中断睡眠（等事件，可被信号唤醒）
D不可中断睡眠（等 I/O，kill -9 也杀不掉）
T停止（收到 SIGSTOP）
Z僵尸
+前台进程组成员

（四）查看与管理进程

命令侧重点
ps -ef全量进程，看 PID / PPID / 启动命令
ps -aux全量进程，看 %CPU / %MEM / STAT
`ps -ef \grep xxx`按名字过滤
top动态刷新，看实时资源占用
pstree -p树状展示父子关系
kill -9 PID强杀（SIGKILL，不可捕获）
kill -15 PID请求退出（SIGTERM，可捕获做清理）

ps -ef 的关键两列：

  • PID：进程唯一标识，内核分配，回收后可复用。
  • PPID：父进程号。所有用户进程最终都追到 1 号进程。

扩展 · /proc 是进程的窗口：cat /proc/PID/status 看状态与内存，ls -l /proc/PID/fd 看打开的文件描述符，cat /proc/PID/cmdline 看启动参数。排查「文件被谁占着」时，lsof 或 ls -l /proc/*/fd 比 ps 有用得多。

（五）0 号、1 号与两类异常进程

名称说明
0 号进程（swapper）内核引导阶段创建，负责进程调度，用户态不可见
1 号进程（init / systemd）所有用户态进程的祖先，负责收养孤儿
孤儿进程父进程先退出，子进程被 1 号（或 systemd --user、桌面会话进程）收养
僵尸进程子进程已退出，父进程未 wait，只剩一个 task 结构占着 PID
  • 孤儿进程无害：它被收养后正常执行、正常退出，只是 PPID 变成了 1。
  • 僵尸进程有害：它不占 CPU、不占内存（除了一点内核结构），但占着 PID。大量僵尸会耗尽 PID 表（/proc/sys/kernel/pid_max），导致无法创建新进程。

易错点：kill -9 杀不掉僵尸。僵尸已经是「尸体」，信号对它无意义；唯一办法是让它的父进程调用 wait/waitpid 回收，或者杀掉父进程让僵尸被 1 号收养后回收。
