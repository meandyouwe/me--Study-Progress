# 10. 信号

信号是内核向进程投递的「软中断」：它异步到达，打断当前执行流，转去执行处理函数，处理完再回到断点。播放器的暂停、切歌、退出，全部靠它驱动。

## （一）信号与中断的关系

| 对比项 | 硬件中断 | 信号 |
|---|---|---|
| 发起者 | 外设 / CPU 异常 | 内核、其他进程、终端 |
| 作用对象 | CPU | 进程 |
| 响应方式 | 跳转中断服务程序 | 跳转信号处理函数 |
| 是否可屏蔽 | 可（关中断） | 可（阻塞信号） |
| 上下文 | 内核态 | 用户态（处理函数在用户态执行） |

所以信号常被称作「软中断」：机制同构，但完全由软件触发。

## （二）62 个信号的编号规则

Linux 共有 62 个信号，编号不连续：

| 区间 | 数量 | 来源 | 特点 |
|---|---|---|---|
| 1–31 | 31 | 继承自 Unix 传统信号 | 编号固定，含义标准化 |
| 32–33 | 2 | 内核内部保留（`SIGCANCEL`/`SIGSETXID`，NPTL 使用） | 用户不可用 |
| 34–64 | 31 | Linux 实时信号（`SIGRTMIN` ~ `SIGRTMAX`） | 支持排队，不丢失 |

教材说的「前 31 个 + 后 31 个」即 1–31 与 34–64，中间的 32、33 被线程库占用了。

## （三）必须记住的信号

| 编号 | 名称 | 默认动作 | 触发方式 / 含义 |
|---|---|---|---|
| 1 | `SIGHUP` | 终止 | 终端挂断；守护进程常约定为重载配置 |
| 2 | `SIGINT` | 终止 | **Ctrl+C** |
| 3 | `SIGQUIT` | 终止 + core | **Ctrl+\\** |
| 6 | `SIGABRT` | 终止 + core | `abort()` |
| 9 | `SIGKILL` | 终止 | **不可捕获、不可忽略** |
| 11 | `SIGSEGV` | 终止 + core | 段错误（空指针、越界） |
| 13 | `SIGPIPE` | 终止 | 向已关闭的管道/套接字写 |
| 14 | `SIGALRM` | 终止 | `alarm()` 计时到 |
| 15 | `SIGTERM` | 终止 | `kill` 默认信号，可捕获做清理 |
| 17 | `SIGCHLD` | 忽略 | **子进程状态改变**（退出、暂停、继续） |
| 18 | `SIGCONT` | 继续 | 恢复被暂停的进程 |
| 19 | `SIGSTOP` | 暂停 | **不可捕获、不可忽略** |
| 20 | `SIGTSTP` | 暂停 | **Ctrl+Z** |

> 关键判据：`SIGKILL`（9）与 `SIGSTOP`（19）是仅有的两个「既不能捕获也不能忽略」的信号，这是内核的兜底设计——否则一个死循环的程序将无法被终止。

## （四）发送信号：kill 与 raise

```c
#include <signal.h>
int kill(pid_t pid, int sig);   /* 成功 0，失败 -1 */
int raise(int sig);             /* 自己给自己发，成功 0 */
```

`kill` 的 `pid` 取值有四种语义：

| `pid` | 含义 |
|---|---|
| `> 0` | 发给指定进程 |
| `== 0` | 发给**同进程组**的所有进程 |
| `== -1` | 发给所有有权限的进程（除 1 号） |
| `< -1` | 发给进程组 ID 为 `-pid` 的所有进程 |

命令行对应写法：

```bash
kill -9 1234          # 强杀
kill -19 1234         # 暂停
kill -18 1234         # 继续
kill -l               # 列出所有信号名
```

`raise(sig)` 等价于 `kill(getpid(), sig)`，常用于程序内部触发自身处理逻辑。

> 权限规则：普通进程只能给**同 UID** 的进程发信号，`root` 可以给任何进程发。发不出去返回 `-1`，`errno = EPERM`。

## （五）捕获信号：signal

```c
#include <signal.h>
typedef void (*sighandler_t)(int);
sighandler_t signal(int signum, sighandler_t handler);
```

`handler` 三种取值：

| 取值 | 含义 |
|---|---|
| `SIG_DFL` | 恢复默认动作 |
| `SIG_IGN` | 忽略该信号（9、19 除外） |
| 自定义函数名 | 捕获并执行该函数 |

自定义处理函数的签名固定为 `void func(int sig)`，参数是收到的信号编号：

```c
void on_sig(int sig)
{
    if (sig == SIGINT)  printf("收到 Ctrl+C\n");
}

int main(void)
{
    signal(SIGINT, on_sig);        /* 注册 */
    while (1) pause();             /* 挂起，等信号 */
    return 0;
}
```

> 易错点：`signal` 的返回值是「之前的处理函数指针」，失败返回 `SIG_ERR`。想「注册后恢复原样」必须保存返回值，不能假设原来是 `SIG_DFL`。

## （六）SIGCHLD：异步回收子进程

子进程退出、暂停、继续都会给父进程发 `SIGCHLD`（17）。这是「父进程不用 `wait` 阻塞也能知道子进程结束」的机制。

```c
void on_child(int sig)
{
    int st;
    pid_t pid;
    while ((pid = waitpid(-1, &st, WNOHANG)) > 0) {
        printf("子进程 %d 结束\n", pid);
    }
}

int main(void)
{
    signal(SIGCHLD, on_child);
    /* ... */
}
```

必须用 `while` 循环而非单次 `waitpid`，原因有两层：

1. `SIGCHLD` 是**不可排队**的普通信号，多个子进程同时退出只会产生一个信号，单次 `wait` 会漏掉其余子进程，留下僵尸。
2. `WNOHANG` 保证没有可回收子进程时立即返回 0，不会卡在信号处理函数里。

> 扩展 · 信号处理的三大禁忌：
> 1. **不可重入函数**：处理函数里调 `printf`、`malloc` 是危险的（它们内部有锁，可能死锁）。真正安全的只有 `write`、`_exit`、`kill` 等「异步信号安全」函数（`man 7 signal-safety`）。
> 2. **必须 `volatile sig_atomic_t`**：处理函数与主流程共享的标志位要用 `volatile sig_atomic_t flag;`，否则编译器优化会把 `while (!flag);` 优化成死循环。
> 3. **不可假设执行流**：信号随时可能打断任意一行代码，处理函数里不能访问可能处于中间状态的数据结构。

## （七）signal 与 sigaction

`signal` 在不同 Unix 上的语义不一致（是否自动重置、是否阻塞自身），POSIX 推荐用 `sigaction`：

```c
#include <signal.h>
struct sigaction sa = {0};
sa.sa_handler = on_child;
sigemptyset(&sa.sa_mask);
sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;   /* 自动重启被中断的系统调用 */
sigaction(SIGCHLD, &sa, NULL);
```

| 对比项 | `signal` | `sigaction` |
|---|---|---|
| 可移植性 | 语义随实现变化 | POSIX 统一 |
| 是否可带标志 | 否 | 是（`SA_RESTART`、`SA_NODEFER` 等） |
| 是否可取旧值 | 返回函数指针 | 第三参数取完整结构 |
| 信号屏蔽 | 不可控 | `sa_mask` 精确控制 |

`SA_RESTART` 解决的是「慢系统调用被信号打断返回 `EINTR`」问题：`read`、`accept`、`wait` 被打断后自动重试，而不是把 `-1` 抛给调用者。

## （八）完整案例：键盘控制子进程

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>

void on_chld(int sig) { waitpid(-1, NULL, WNOHANG); }

int main(void)
{
    signal(SIGCHLD, on_chld);

    pid_t pid = fork();
    if (pid == 0) {
        while (1) { printf("i am son\n"); sleep(1); }
    }

    char ch;
    while ((ch = getchar()) != EOF) {
        switch (ch) {
        case 's': kill(pid, SIGSTOP);  break;   /* 暂停 */
        case 'c': kill(pid, SIGCONT);  break;   /* 继续 */
        case 'q': kill(pid, SIGKILL);  return 0;
        }
    }
    return 0;
}
```

这段代码就是「无界面 MP3 播放器」的骨架：`mpg123` 换成子进程，`SIGSTOP`/`SIGCONT` 实现暂停继续，`SIGKILL` + 重新 `fork` 实现切歌。

> 易错点：`mpg123` 会关闭终端回显、隐藏光标（「吃终端」）。程序退出前必须恢复，否则终端输入看不见。用 `atexit` 注册两行恢复代码：`system("stty echo"); printf("\033[?25h");`。
