3. 标准 I/O：缓冲文件操作

标准 I/O 的核心抽象是 FILE *——一个「文件描述符 + 用户态缓冲区 + 读写位置 + 错误标志」的结构体指针。它的价值是把「每次读写都陷内核」变成「攒够一批再陷内核」。

（二）缓冲区的四个刷新时机

printf 的输出去向不是终端，而是缓冲区。数据真正落到内核，只在这四种情况：

  1. 遇到换行符 \n（仅行缓冲，即输出到终端时）；
  2. 缓冲区写满（大小由实现决定，BUFSIZ 通常为 8192，部分教材写 1024）；
  3. 程序正常结束（return 从 main 返回，或调用 exit）；
  4. 手动调用 fflush(fp)。

三种缓冲类型：全缓冲（重定向到文件/管道时的默认）、行缓冲（终端）、无缓冲（stderr 固定无缓冲，保证错误信息立即出现）。

易错点：while(1) { printf("."); sleep(1); } 在重定向到文件时不输出任何内容，因为既没换行也没满 8 KB。加 fflush(stdout) 或用 stderr 才能实时看到。

（六）一个完整的作业范例及其缺陷

教材的「用户名密码」程序用 fwrite 存结构体、fread 读回，再循环三次校验。核心逻辑没问题，但输入循环里有两处典型缺陷：

i-- 让循环体与 for 更新表达式各减一次，实际只给两次机会；且 printf 打印的是「减之前」的值，提示与实际次数对不上。正确写法是打印 i - 1，绝不动循环变量。

%s 不限制长度，输入超过 19 字节就会覆盖结构体后续内存。应写 %19s，或用 fgets 读入后 strtok 切分。

扩展 · 更稳妥的输入封装：fgets 读到换行后再 sscanf，既能限长又能处理整行；交互式程序还要考虑清空残留输入（while ((c = getchar()) != '\n' && c != EOF);），否则下一次读会立刻拿到上一次的残余。

（七）标准 I/O 的适用边界

标准 I/O 适合普通文件和格式化文本。它不适合三类场景：需要精确控制每次系统调用的量（网络、管道）、需要用非文件句柄（套接字、设备）、需要多个进程共享同一打开文件。这三类都要下沉到系统调用层，也就是下一章的内容。
