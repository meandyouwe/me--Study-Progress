# 3. 标准 I/O：缓冲文件操作

标准 I/O 的核心抽象是 `FILE *`——一个「文件描述符 + 用户态缓冲区 + 读写位置 + 错误标志」的结构体指针。它的价值是把「每次读写都陷内核」变成「攒够一批再陷内核」。

## （一）打开与关闭

```c
FILE *fp = fopen("user.dat", "wb+");
if (fp == NULL) {
    perror("fopen");
    return -1;
}
/* ... */
fclose(fp);          /* 成功返回 0，失败返回 EOF */
```

| 模式 | 读 | 写 | 文件不存在 | 文件存在 |
|---|---|---|---|---|
| `r` | ✓ | ✗ | 失败 | 从开头读 |
| `r+` | ✓ | ✓ | 失败 | 从开头读写 |
| `w` | ✗ | ✓ | 创建 | **清空** |
| `w+` | ✓ | ✓ | 创建 | **清空** |
| `a` | ✗ | ✓ | 创建 | 追加写 |
| `a+` | ✓ | ✓ | 创建 | 读任意位置，写始终追加 |

加 `b` 表示二进制模式。Linux 下 `b` 无实际作用（不转换 `\r\n`），但跨平台代码必须写，否则在 Windows 上读写结构体会错位。

## （二）缓冲区的四个刷新时机

`printf` 的输出去向不是终端，而是缓冲区。数据真正落到内核，只在这四种情况：

1. 遇到换行符 `\n`（**仅行缓冲**，即输出到终端时）；
2. 缓冲区写满（大小由实现决定，`BUFSIZ` 通常为 8192，部分教材写 1024）；
3. 程序正常结束（`return` 从 `main` 返回，或调用 `exit`）；
4. 手动调用 `fflush(fp)`。

三种缓冲类型：**全缓冲**（重定向到文件/管道时的默认）、**行缓冲**（终端）、**无缓冲**（`stderr` 固定无缓冲，保证错误信息立即出现）。

```c
#include <stdio.h>
int fflush(FILE *stream);      /* 成功 0，失败 EOF */
```

> 易错点：`while(1) { printf("."); sleep(1); }` 在重定向到文件时不输出任何内容，因为既没换行也没满 8 KB。加 `fflush(stdout)` 或用 `stderr` 才能实时看到。

## （三）默认打开的三个流

程序启动时内核已经准备好三个描述符，标准库把它们包装成流指针：

| 流 | 描述符 | 默认缓冲 | 用途 |
|---|---|---|---|
| `stdin` | 0 | 行缓冲 | 标准输入 |
| `stdout` | 1 | 行缓冲（终端）/全缓冲（重定向） | 标准输出 |
| `stderr` | 2 | 无缓冲 | 错误输出 |

## （四）字符、行、格式化、块：四组读写函数

| 组 | 写 | 读 | 特点 |
|---|---|---|---|
| 字符 | `fputc` / `putc` / `putchar` | `fgetc` / `getc` / `getchar` | 单字节，适合逐字符处理 |
| 行 | `fputs` / `puts` | `fgets` / `gets`（**已废弃**） | 以 `\n` 或 `EOF` 为界 |
| 格式化 | `fprintf` / `printf` / `sprintf` / `snprintf` | `fscanf` / `scanf` / `sscanf` | 文本可读，解析开销大 |
| 块 | `fwrite` | `fread` | 二进制整块，效率最高 |

结构体整块存取的标准写法：

```c
typedef struct {
    int   account;
    char  passwd[20];
} USER;

USER info = {0};
fread(&info, sizeof(info), 1, fp);        /* 返回值是"成功读到的块数" */
fwrite(&info, sizeof(info), 1, fp);
```

> 易错点：`fread` 的返回值是**块数**而不是字节数。若按字节判断，写成 `if (fread(buf, 1, n, fp) < n)` 才正确（此时块大小为 1，块数即字节数）。混用 `sizeof(info)` 与字节判断会漏读。

> 易错点：`sizeof(info)` 包含结构体填充字节，跨编译器/跨架构直接读写会错位。需要长期存储或跨平台交换时，用定长类型（`uint32_t`）+ 逐字段序列化，或改用文本格式（JSON/CSV）。

## （五）定位与状态

```c
int   fseek(FILE *fp, long offset, int whence);   /* SEEK_SET/CUR/END，成功 0 */
long  ftell(FILE *fp);                            /* 当前偏移，失败 -1 */
void  rewind(FILE *fp);                           /* 等价 fseek(fp,0,SEEK_SET) 并清错误标志 */
int   feof(FILE *fp);                             /* 已读到末尾返回非 0 */
int   ferror(FILE *fp);                           /* 出错返回非 0 */
void  clearerr(FILE *fp);                         /* 清除两个标志 */
```

`feof` 的经典误用：

```c
/* 错误：多输出一行 */
while (!feof(fp)) {
    fgets(buf, sizeof(buf), fp);
    printf("%s", buf);
}

/* 正确：以读函数的返回值判断 */
while (fgets(buf, sizeof(buf), fp) != NULL) {
    printf("%s", buf);
}
```

原因：`feof` 只有在**读过末尾之后**才置位，它描述的是「上一次读的结果」，不是「下一次读会不会成功」。

## （六）一个完整的作业范例及其缺陷

教材的「用户名密码」程序用 `fwrite` 存结构体、`fread` 读回，再循环三次校验。核心逻辑没问题，但输入循环里有两处典型缺陷：

```c
for (int i = 3; i > 0; i--) {
    /* ... */
    printf("还剩%d 次机会\n", i--);   /* 缺陷 1：循环变量在循环体内又被减一次 */
}
```

`i--` 让循环体与 `for` 更新表达式各减一次，实际只给两次机会；且 `printf` 打印的是「减之前」的值，提示与实际次数对不上。正确写法是打印 `i - 1`，绝不动循环变量。

```c
scanf("%d%s", &info.account, info.passwd);   /* 缺陷 2：无长度限制 */
```

`%s` 不限制长度，输入超过 19 字节就会覆盖结构体后续内存。应写 `%19s`，或用 `fgets` 读入后 `strtok` 切分。

> 扩展 · 更稳妥的输入封装：`fgets` 读到换行后再 `sscanf`，既能限长又能处理整行；交互式程序还要考虑清空残留输入（`while ((c = getchar()) != '\n' && c != EOF);`），否则下一次读会立刻拿到上一次的残余。

## （七）标准 I/O 的适用边界

标准 I/O 适合**普通文件**和**格式化文本**。它不适合三类场景：需要精确控制每次系统调用的量（网络、管道）、需要用非文件句柄（套接字、设备）、需要多个进程共享同一打开文件。这三类都要下沉到系统调用层，也就是下一章的内容。
