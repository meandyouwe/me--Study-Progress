10. 信号

信号是内核向进程投递的「软中断」：它异步到达，打断当前执行流，转去执行处理函数，处理完再回到断点。播放器的暂停、切歌、退出，全部靠它驱动。

（一）信号与中断的关系

对比项硬件中断信号
发起者外设 / CPU 异常内核、其他进程、终端
作用对象CPU进程
响应方式跳转中断服务程序跳转信号处理函数
是否可屏蔽可（关中断）可（阻塞信号）
上下文内核态用户态（处理函数在用户态执行）

所以信号常被称作「软中断」：机制同构，但完全由软件触发。

（二）62 个信号的编号规则

Linux 共有 62 个信号，编号不连续：

区间数量来源特点
1–3131继承自 Unix 传统信号编号固定，含义标准化
32–332内核内部保留（SIGCANCEL/SIGSETXID，NPTL 使用）用户不可用
34–6431Linux 实时信号（SIGRTMIN ~ SIGRTMAX）支持排队，不丢失

教材说的「前 31 个 + 后 31 个」即 1–31 与 34–64，中间的 32、33 被线程库占用了。

（三）必须记住的信号

编号名称默认动作触发方式 / 含义
1SIGHUP终止终端挂断；守护进程常约定为重载配置
2SIGINT终止Ctrl+C
3SIGQUIT终止 + coreCtrl+\\
6SIGABRT终止 + coreabort()
9SIGKILL终止不可捕获、不可忽略
11SIGSEGV终止 + core段错误（空指针、越界）
13SIGPIPE终止向已关闭的管道/套接字写
14SIGALRM终止alarm() 计时到
15SIGTERM终止kill 默认信号，可捕获做清理
17SIGCHLD忽略子进程状态改变（退出、暂停、继续）
18SIGCONT继续恢复被暂停的进程
19SIGSTOP暂停不可捕获、不可忽略
20SIGTSTP暂停Ctrl+Z

关键判据：SIGKILL（9）与 SIGSTOP（19）是仅有的两个「既不能捕获也不能忽略」的信号，这是内核的兜底设计——否则一个死循环的程序将无法被终止。

（四）发送信号：kill 与 raise

kill 的 pid 取值有四种语义：

pid含义
> 0发给指定进程
== 0发给同进程组的所有进程
== -1发给所有有权限的进程（除 1 号）
< -1发给进程组 ID 为 -pid 的所有进程

命令行对应写法：

raise(sig) 等价于 kill(getpid(), sig)，常用于程序内部触发自身处理逻辑。

权限规则：普通进程只能给同 UID 的进程发信号，root 可以给任何进程发。发不出去返回 -1，errno = EPERM。

（六）SIGCHLD：异步回收子进程

子进程退出、暂停、继续都会给父进程发 SIGCHLD（17）。这是「父进程不用 wait 阻塞也能知道子进程结束」的机制。

必须用 while 循环而非单次 waitpid，原因有两层：

  1. SIGCHLD 是不可排队的普通信号，多个子进程同时退出只会产生一个信号，单次 wait 会漏掉其余子进程，留下僵尸。
  2. WNOHANG 保证没有可回收子进程时立即返回 0，不会卡在信号处理函数里。

扩展 · 信号处理的三大禁忌：

1. 不可重入函数：处理函数里调 printf、malloc 是危险的（它们内部有锁，可能死锁）。真正安全的只有 write、_exit、kill 等「异步信号安全」函数（man 7 signal-safety）。

2. 必须 volatile sig_atomic_t：处理函数与主流程共享的标志位要用 volatile sig_atomic_t flag;，否则编译器优化会把 while (!flag); 优化成死循环。

3. 不可假设执行流：信号随时可能打断任意一行代码，处理函数里不能访问可能处于中间状态的数据结构。

（七）signal 与 sigaction

signal 在不同 Unix 上的语义不一致（是否自动重置、是否阻塞自身），POSIX 推荐用 sigaction：

对比项signalsigaction
可移植性语义随实现变化POSIX 统一
是否可带标志否是（SA_RESTART、SA_NODEFER 等）
是否可取旧值返回函数指针第三参数取完整结构
信号屏蔽不可控sa_mask 精确控制

SA_RESTART 解决的是「慢系统调用被信号打断返回 EINTR」问题：read、accept、wait 被打断后自动重试，而不是把 -1 抛给调用者。
