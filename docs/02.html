2. 数据类型与变量

（一）基本类型与长度

类型典型长度说明
char1 字节字符型，C 中即最小整型
short2 字节短整型
int4 字节最常用整型
long4 或 8 字节长度依赖平台：Windows 64 位为 4，Linux 64 位为 8
long long8 字节跨平台稳定的 64 位整型
float4 字节单精度，约 6~7 位有效数字
double8 字节双精度，约 15~16 位有效数字
指针4 或 8 字节与平台地址宽度一致

长度不是"背下来的"，而是用 sizeof 查出来的。sizeof 的返回类型是 size_t，printf 时应使用 %zu，写成 %d 在 64 位平台属未定义行为。

再补两点：sizeof 不是函数，是运算符，也是 32 个关键字之一，表达式在编译期就求值；所以 sizeof(float) 直接得到 4，不需要任何头文件，也不能当作函数指针传递。

（二）取值范围与整型溢出

以 32 位 int 为例：signed int 范围是 -2147483648 ~ 2147483647，unsigned int 是 0 ~ 4294967295。

  • 有符号整型溢出是未定义行为（UB），不是"变成负数"这么简单，编译器可据此做任意优化。
  • 无符号整型按 2 的模回绕（0u - 1 得到 4294967295），行为有定义，但通常不是想要的结果。

（三）常量与字面量

写法含义备注
10、0x1F、017十进制 / 十六进制 / 八进制以 0 开头是八进制，010 等于 8
10U、10L、10LL无符号 / long / long long后缀大小写均可
1.5、1.5fdouble / float不加 f 是 double
'A'、'\n'、'\\'字符常量单引号，本质是 int
"A"字符串常量双引号，含结尾 '\0'，长度为 2

字符常量除了直接写字面字符，还能用转义写法表示任意编码：'\101' 是八进制转义（\ 后最多 3 位八进制数字，101 即十进制 65，也就是 'A'）；'\x41' 是十六进制转义（\x 后跟十六进制数字）。区别只在有没有那个 x —— 同一个字符 'A'，两种写法都成立。

（四）类型转换

  • 隐式转换：赋值、算术运算、函数传参时自动进行，小类型向大类型提升（整数提升、寻常算术转换）。
  • 显式转换：(double)a / b，明确意图，也便于阅读。

两个高频陷阱：

  1. 整数除法截断：5 / 2 得 2，想得到 2.5 必须写 5.0 / 2 或 (double)5 / 2。
  2. 有符号与无符号混比：int i 与 unsigned n 比较时，i 会被转换为无符号数；for (int i = n - 1; i >= 0; i--) 若 n 为无符号，条件恒真，直接死循环或越界。

再补两条同样高频的：

  1. 浮点转整型是截断，不是四舍五入：(int)3.99 得 3，(int)-3.99 得 -3（向零取整）。要四舍五入得显式调用 round()。
  2. 算式中只要出现无符号数，其余操作数都转为无符号：int 与 unsigned 混合运算时，int 也被转成 unsigned，-1 变成 4294967295，除法、比较、取模的结果都会反直觉。这是"有符号/无符号混比"那条的完整版，写 if (i < n) 之前先确认两边类型一致。

（五）程序的内存分区

一个运行中的程序，内存按用途被切成几个区段。搞清"变量住在哪"，才能解释为什么有些赋值会崩、有些变量有初值、有些是垃圾值。

区段存放内容读写属性生命周期
代码段 .text机器指令、switch 跳转表只读、可执行整个运行期
常量区 .rodata字符串字面量、const 全局量、static const只读整个运行期
全局/静态区 .data已初始化的全局变量、static可读写整个运行期
全局/静态区 .bss未初始化（或初始化为 0）的全局、static可读写启动时清零
栈局部变量、函数参数、返回地址可读写函数调用期间，自动回收
堆malloc / calloc / realloc 分配可读写手动 free

常量区最需要记住的一点是：它被操作系统映射为只读页。往这里写不是"值没改成功"，而是进程被当场终止。

  • const 不等于落在常量区：const 局部变量通常仍在栈上，只是编译器禁止你写；真正只读的是字符串字面量和 const 全局量，写它们必崩。
  • 想改内容就别指向字面量：char buf[] = "hello"; 或 char buf[32]; strcpy(buf, "hello"); 都行，char *p = "hello"; 不行。
  • 崩溃特征：报段错误（Linux）或"写入位置 0x… 时发生访问冲突"（Windows），地址通常很低，因为它落在可执行文件映射的只读段里。
  • 判断口诀：要修改 → 用数组或堆；只共享只读文本 → 用 const char *。
