# 4. 系统 I/O：文件描述符与非缓冲操作

标准 I/O 之下是系统调用层。这一层没有缓冲区、没有格式化，只有五个原语：`open`、`close`、`read`、`write`、`lseek`。所有高级 I/O（管道、套接字、设备）都建立在这五个之上。

## （一）为什么必须学非缓冲 I/O

教材给的三个理由是准确的，但可以再往深一层：

1. **特殊文件没有 `FILE *`**：管道、套接字、字符设备的句柄是 `int` 类型的描述符，标准库没有对应的流，只能走系统调用。
2. **缓冲区不可控**：实时性要求高的场景（串口、传感器）不能被 8 KB 缓冲拖住。
3. **需要精细控制**：`O_NONBLOCK`（非阻塞）、`O_SYNC`（同步落盘）、`O_APPEND`（原子追加）这些语义只存在于系统调用层。

## （二）open：flags 与 mode

```c
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>

int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);
```

| flags | 含义 | 备注 |
|---|---|---|
| `O_RDONLY` | 只读 | 值为 0，**不能**用 `if (flags & O_RDONLY)` 判断 |
| `O_WRONLY` | 只写 | 1 |
| `O_RDWR` | 读写 | 2 |
| `O_CREAT` | 不存在则创建 | 必须提供第三个参数 `mode` |
| `O_EXCL` | 与 `O_CREAT` 合用，已存在则失败 | 实现「原子创建锁文件」 |
| `O_TRUNC` | 存在则清空 | 只写/读写模式下生效 |
| `O_APPEND` | 每次写前定位到末尾 | 内核保证原子性，多进程安全 |
| `O_NONBLOCK` | 非阻塞 | 管道、设备、套接字场景 |
| `O_SYNC` | 写操作同步落盘 | 性能代价大 |

返回值：成功返回**最小的可用描述符**（0/1/2 被占用，所以通常从 3 开始），失败返回 `-1` 并设置 `errno`。

## （三）权限：mode 与 umask 的与运算

新建文件的最终权限不是 `mode` 本身，而是：

```
真实权限 = mode & ~umask
```

以 `mode = 0666`、`umask = 0002` 为例：

```
  110 110 110   (0666)
& 111 111 101   (~0002)
---------------
  110 110 100   (0664)
```

即 `rw-rw-r--`。`umask` 是「要屏蔽掉的位」，通常 `root` 为 `0022`，普通用户为 `0002`。

> 易错点：`open("f", O_CREAT)` 只给两个参数是未定义行为——`mode` 会从栈上取到随机值。只要 `flags` 里有 `O_CREAT`，就必须写第三个参数。

> 扩展 · 安全创建：`open(path, O_WRONLY|O_CREAT|O_EXCL, 0600)` 是「创建临时文件/锁文件」的标准写法，`O_EXCL` 保证「检查存在」与「创建」是一个原子操作，能避免两个进程同时判断「文件不存在」然后互相覆盖。

## （四）read / write：字节数语义

```c
ssize_t write(int fd, const void *buf, size_t count);   /* 成功返回实际写入字节数 */
ssize_t read (int fd, void *buf, size_t count);         /* 成功返回实际读到字节数，0 表示 EOF */
```

要点：

- 返回值类型 `ssize_t`（有符号），失败为 `-1`，**不要**用 `size_t` 接收，否则 `-1` 会变成巨大正数。
- `count` 的取法：写结构体用 `sizeof`，写字符串用 `strlen`（**不含** `\0`，否则文件里多一个不可见字节）。
- `read` 可能**短读**：请求 4096 字节只返回 100 字节是合法的（管道、终端、网络常见）。完整读取必须循环：

```c
ssize_t total = 0, n;
while (total < size && (n = read(fd, buf + total, size - total)) > 0) {
    total += n;
}
if (n < 0) perror("read");
```

- `write` 同理可能**短写**，尤其是写入超过管道缓冲区（默认 64 KB）时。

> 易错点：`while (read(fd, &ch, 1))` 在 `read` 返回 `-1` 时条件为真，会死循环。必须写 `while (read(fd, &ch, 1) > 0)`。

## （五）lseek：定位与「求大小」

```c
#include <sys/types.h>
#include <unistd.h>
off_t lseek(int fd, off_t offset, int whence);
```

`whence` 三个取值：`SEEK_SET`（文件开头）、`SEEK_CUR`（当前位置）、`SEEK_END`（文件末尾）。成功返回「新位置距文件开头的字节数」，失败 `-1`。

三个高频用法：

```c
off_t size = lseek(fd, 0, SEEK_END);   /* 求文件大小 */
lseek(fd, 0, SEEK_SET);                /* 回到开头再读 */
off_t cur  = lseek(fd, 0, SEEK_CUR);   /* 当前位置 */
```

`lseek` 允许定位到文件末尾之外，之后再写会形成**空洞文件**，空洞不占磁盘块但 `ls` 显示的大小会增大。`lseek` **不能**用于管道和套接字（返回 `-1`，`errno = ESPIPE`）。

## （六）缓冲与非缓冲的对应关系

| 标准 I/O | 系统调用 | 说明 |
|---|---|---|
| `fopen` | `open` | 建立流与描述符的绑定 |
| `fclose` | `close` | 先 `fflush` 再 `close` |
| `fread` / `fwrite` | `read` / `write` | 前者带缓冲，可短读 |
| `fseek` / `ftell` | `lseek` | 前者维护用户态偏移 |
| `fflush` | 无 | 把用户态缓冲刷进内核 |
| `fileno(fp)` | 无 | 取出流内部的描述符 |

> 扩展 · 内核里的三层结构：**描述符表**（每进程一份，索引 → 打开文件表项）、**打开文件表**（系统级，记录偏移与 flags）、**inode 表**（文件元数据）。`fork` 复制描述符表但共享打开文件表项，所以父子进程共享文件偏移——这是「父进程读一半，子进程从剩下一半继续读」的根因。`dup2` 复制的也是表项指针，重定向（`./a.out > out.txt`）正是靠它实现。

## （七）cp 的四种实现与取舍

教材给了四种写法，实际工程中只有一种可用：

| 方案 | 代码量 | 内存 | 适用场景 |
|---|---|---|---|
| 读 1 字节写 1 字节 | 最少 | 2 字节 | 教学演示，性能极差 |
| 读 N 写 N（定长缓冲） | 少 | 4 KB | **推荐**，通用 |
| 一次读全部（数组足够大） | 少 | 栈上 4 KB，易溢出 | 不推荐，大文件直接崩 |
| `malloc` + `lseek` 求长 | 中 | 等于文件大小 | 小文件可用，大文件 OOM |

正确写法必须是「循环 + 以返回值为准」：

```c
char buf[4096];
ssize_t n;
while ((n = read(fd1, buf, sizeof(buf))) > 0) {
    ssize_t off = 0;
    while (off < n) {                       /* 处理短写 */
        ssize_t w = write(fd2, buf + off, n - off);
        if (w < 0) { perror("write"); return -1; }
        off += w;
    }
}
if (n < 0) perror("read");
```

> 扩展 · `sendfile(2)` 可以让内核在两个描述符之间直接搬运，零拷贝，`cp` 大文件时性能显著优于用户态循环。
