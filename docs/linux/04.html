4. 系统 I/O：文件描述符与非缓冲操作

标准 I/O 之下是系统调用层。这一层没有缓冲区、没有格式化，只有五个原语：open、close、read、write、lseek。所有高级 I/O（管道、套接字、设备）都建立在这五个之上。

（一）为什么必须学非缓冲 I/O

教材给的三个理由是准确的，但可以再往深一层：

  1. 特殊文件没有 FILE *：管道、套接字、字符设备的句柄是 int 类型的描述符，标准库没有对应的流，只能走系统调用。
  2. 缓冲区不可控：实时性要求高的场景（串口、传感器）不能被 8 KB 缓冲拖住。
  3. 需要精细控制：O_NONBLOCK（非阻塞）、O_SYNC（同步落盘）、O_APPEND（原子追加）这些语义只存在于系统调用层。

（二）open：flags 与 mode

flags含义备注
O_RDONLY只读值为 0，不能用 if (flags & O_RDONLY) 判断
O_WRONLY只写1
O_RDWR读写2
O_CREAT不存在则创建必须提供第三个参数 mode
O_EXCL与 O_CREAT 合用，已存在则失败实现「原子创建锁文件」
O_TRUNC存在则清空只写/读写模式下生效
O_APPEND每次写前定位到末尾内核保证原子性，多进程安全
O_NONBLOCK非阻塞管道、设备、套接字场景
O_SYNC写操作同步落盘性能代价大

返回值：成功返回最小的可用描述符（0/1/2 被占用，所以通常从 3 开始），失败返回 -1 并设置 errno。

即 rw-rw-r--。umask 是「要屏蔽掉的位」，通常 root 为 0022，普通用户为 0002。

易错点：open("f", O_CREAT) 只给两个参数是未定义行为——mode 会从栈上取到随机值。只要 flags 里有 O_CREAT，就必须写第三个参数。

扩展 · 安全创建：open(path, O_WRONLY|O_CREAT|O_EXCL, 0600) 是「创建临时文件/锁文件」的标准写法，O_EXCL 保证「检查存在」与「创建」是一个原子操作，能避免两个进程同时判断「文件不存在」然后互相覆盖。

（四）read / write：字节数语义

要点：

  • 返回值类型 ssize_t（有符号），失败为 -1，不要用 size_t 接收，否则 -1 会变成巨大正数。
  • count 的取法：写结构体用 sizeof，写字符串用 strlen（不含 \0，否则文件里多一个不可见字节）。

  • write 同理可能短写，尤其是写入超过管道缓冲区（默认 64 KB）时。

易错点：while (read(fd, &ch, 1)) 在 read 返回 -1 时条件为真，会死循环。必须写 while (read(fd, &ch, 1) > 0)。

（五）lseek：定位与「求大小」

whence 三个取值：SEEK_SET（文件开头）、SEEK_CUR（当前位置）、SEEK_END（文件末尾）。成功返回「新位置距文件开头的字节数」，失败 -1。

（六）缓冲与非缓冲的对应关系

标准 I/O系统调用说明
fopenopen建立流与描述符的绑定
fcloseclose先 fflush 再 close
fread / fwriteread / write前者带缓冲，可短读
fseek / ftelllseek前者维护用户态偏移
fflush无把用户态缓冲刷进内核
fileno(fp)无取出流内部的描述符

扩展 · 内核里的三层结构：描述符表（每进程一份，索引 → 打开文件表项）、打开文件表（系统级，记录偏移与 flags）、inode 表（文件元数据）。fork 复制描述符表但共享打开文件表项，所以父子进程共享文件偏移——这是「父进程读一半，子进程从剩下一半继续读」的根因。dup2 复制的也是表项指针，重定向（./a.out > out.txt）正是靠它实现。
