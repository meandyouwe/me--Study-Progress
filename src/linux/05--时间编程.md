# 5. 时间编程

嵌入式与系统编程里的「时间」有三层含义：**日历时间**（人类可读）、**时间戳**（秒数）、**单调时间**（只增不减的计数器）。混用会写出「系统改时间后定时器错乱」这类隐蔽 bug。

## （一）命令行工具

```bash
date                    # 当前日期时间
date +"%F %T"           # 格式化输出 2026-11-25 19:20:44
date -d "1970-01-01 UTC 1700000000 seconds"   # 时间戳反解
cal                     # 本月日历
cal 2026                # 整年
cal 11 2026             # 指定年月
```

## （二）time：取日历时间

```c
#include <time.h>
time_t time(time_t *tloc);
```

返回**自 1970-01-01 00:00:00 UTC 起经过的秒数**（Unix 时间戳）。参数可为 `NULL`，也可传入地址由函数回填。两种写法等价：

```c
time_t t = time(NULL);
time_t t; time(&t);
```

`time_t` 在 32 位系统上是 32 位有符号整数，最大到 2038-01-19 03:14:07，这就是「2038 问题」。现代 64 位 Linux 已改为 64 位。

## （三）struct tm 与转换函数

```c
struct tm {
    int tm_sec;    /* 秒 0-60（60 用于闰秒） */
    int tm_min;    /* 分 0-59 */
    int tm_hour;   /* 时 0-23 */
    int tm_mday;   /* 日 1-31 */
    int tm_mon;    /* 月 0-11  ← 从 0 开始 */
    int tm_year;   /* 年 -1900 ← 需加 1900 */
    int tm_wday;   /* 星期 0-6，周日为 0 */
    int tm_yday;   /* 年内第几天 0-365 */
    int tm_isdst;  /* 夏令时标志 */
};
```

| 函数 | 原型 | 作用 |
|---|---|---|
| `localtime` | `struct tm *localtime(const time_t *)` | 秒数 → 本地时间 |
| `gmtime` | `struct tm *gmtime(const time_t *)` | 秒数 → UTC（比北京时间慢 8 小时） |
| `ctime` | `char *ctime(const time_t *)` | 秒数 → 固定格式字符串 |
| `asctime` | `char *asctime(const struct tm *)` | 结构体 → 固定格式字符串 |
| `strftime` | `size_t strftime(char *, size_t, const char *, const struct tm *)` | 结构体 → 自定义格式 |
| `mktime` | `time_t mktime(struct tm *)` | 本地时间结构体 → 秒数（逆向） |

> 严重易错点：`localtime` 与 `gmtime` 返回的是**指向静态全局变量的指针**。连续调用两次，第一次的结果会被覆盖：

```c
struct tm *a = localtime(&t1);
struct tm *b = localtime(&t2);
printf("%d", a->tm_hour);   /* 已经是 t2 的值！ */
```

多线程环境必须用可重入版本 `localtime_r` / `gmtime_r`（POSIX 扩展，需定义 `_POSIX_C_SOURCE` 或在 Linux 下直接可用）：

```c
struct tm tm_buf;
localtime_r(&t, &tm_buf);
```

## （四）strftime 常用格式符

| 符 | 含义 | 示例 |
|---|---|---|
| `%Y` | 四位年 | 2026 |
| `%m` | 两位月 | 11 |
| `%d` | 两位日 | 25 |
| `%H` `%M` `%S` | 时 分 秒 | 19 20 44 |
| `%F` | 等价 `%Y-%m-%d` | 2026-11-25 |
| `%T` | 等价 `%H:%M:%S` | 19:20:44 |
| `%A` `%B` | 星期全名、月全名 | Wednesday / November |
| `%j` | 年内第几天 | 329 |
| `%p` | AM / PM | PM |
| `%s` | Unix 时间戳 | 1795605644 |
| `%%` | 百分号本身 | % |

```c
char buf[64] = {0};
strftime(buf, sizeof(buf), "%F %T", &tm_buf);    /* 2026-11-25 19:20:44 */
```

> 易错点：`strftime` 返回 0 有两种可能——格式化结果为空串，或**缓冲区不足**。判断失败要看 `errno`，不能只看返回值。

## （五）完整案例：每 5 秒建一个带时间戳的文件

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <time.h>

int main(void)
{
    for (int cnt = 1; cnt <= 10; cnt++) {
        time_t t = time(NULL);
        struct tm *lt = localtime(&t);

        char name[64] = {0};
        strftime(name, sizeof(name), "%F %T", lt);
        strcat(name, ".txt");

        int fd = open(name, O_WRONLY | O_CREAT | O_TRUNC, 0666);
        if (fd < 0) { perror("open"); return -1; }

        char content[64] = {0};
        int len = snprintf(content, sizeof(content), "这是我创建的第%d 个文件", cnt);
        write(fd, content, len);
        close(fd);

        if (cnt < 10) sleep(5);
    }
    return 0;
}
```

教材版本用 `sleep(3)`，与「每 5 秒」的需求不符；另外 `strcat` 前必须保证 `name` 以 `\0` 结尾（`strftime` 成功时会写结束符，但失败时不保证）。

> 扩展 · 更稳的写法：用 `snprintf` 一次成型，避免 `strftime` + `strcat` 两步：

```c
char name[64];
struct tm lt; localtime_r(&t, &lt);
snprintf(name, sizeof(name), "%04d-%02d-%02d %02d:%02d:%02d.txt",
         lt.tm_year + 1900, lt.tm_mon + 1, lt.tm_mday,
         lt.tm_hour, lt.tm_min, lt.tm_sec);
```

## （六）延时与计时

| 函数 | 精度 | 可被信号中断 | 说明 |
|---|---|---|---|
| `sleep(n)` | 秒 | 是，返回剩余秒数 | 最常用 |
| `usleep(us)` | 微秒 | 是 | 已废弃 |
| `nanosleep(&req, &rem)` | 纳秒 | 是，`rem` 给出剩余 | 推荐，精度最高 |
| `clock_gettime(CLOCK_MONOTONIC, &ts)` | 纳秒 | 否 | 测耗时**必须**用它 |

> 扩展 · 为什么测耗时不能用 `time()`：`time()` 的分辨率是 1 秒，且会被系统对时（NTP）向前或向后调整。`CLOCK_MONOTONIC` 从开机起单调递增，不受改时间影响，是测量时间间隔的唯一正确选择。

```c
struct timespec a, b;
clock_gettime(CLOCK_MONOTONIC, &a);
/* ... 被测代码 ... */
clock_gettime(CLOCK_MONOTONIC, &b);
double ms = (b.tv_sec - a.tv_sec) * 1000.0 + (b.tv_nsec - a.tv_nsec) / 1e6;
```
