# 1. 课程地图：从系统编程到图形界面

本课程的主线是「让程序脱离 C 标准库的舒适区，直接与内核打交道」：文件、时间、目录、进程、信号，最后用 LVGL 把这些能力包装成可交互的界面。五个 PDF 对应五个能力层，彼此不是并列关系，而是逐层收窄的依赖链。

## （一）知识依赖链

把章节按依赖关系排开，可以看清为什么顺序不能乱：

| 层 | 主题 | 前置依赖 | 没有它会卡在哪里 |
|---|---|---|---|
| L1 | 工程组织（Makefile、库） | C 语言基础 | 多文件编译、链接第三方库全部失败 |
| L2 | 标准 I/O（`FILE *`） | L1 | 只能写单文件小 demo |
| L3 | 系统 I/O（`fd`） | L2、`errno` | 管道、套接字、设备文件无从下手 |
| L4 | 时间与目录 | L3 | 做不出带时间戳的日志、遍历不了目录 |
| L5 | 文件属性（`stat`） | L4 | 实现不了 `ls -l`、判断不了文件类型 |
| L6 | 进程（`fork`/`exec`） | L3 | 无法调用外部程序、无法并行 |
| L7 | 信号（`signal`） | L6 | 无法异步通知、无法优雅停止子进程 |
| L8 | LVGL（图形界面） | L6、L7（线程） | 界面里的播放控制没有事件驱动模型 |

> 判据：任何一次「调不通」，先回到上表定位缺的是哪一层。`perror` 报 `No such file or directory` 是 L3 的路径问题，不是 L6 的进程问题。

## （二）三条并行的能力线

课程内容看似零散，实际只有三条线：

1. **资源线**：文件描述符 → 目录流 → 进程号。三者都是「整数句柄 + 打开/使用/关闭」的同一套模式，`open/close`、`opendir/closedir`、`fork/wait` 结构完全同构。
2. **时间线**：`time` 取秒数 → `localtime` 转结构体 → `strftime` 格式化。所有「按时间命名文件」「界面显示时钟」的需求都是这三步的排列组合。
3. **控制线**：`fork` 造进程 → `exec` 换程序 → `kill` 发信号 → `wait` 收尸。播放器、守护进程、Shell 全部由这套原语拼出来。

> 扩展 · 为什么强调「同构」：Linux 的设计哲学是「一切皆文件」，句柄化（handle）统一了设备、管道、套接字、目录。理解了这个抽象，`open` 的 `flags` 参数就能迁移到 `socket` 的 `type` 参数上，学习成本骤降。

## （三）每章的产出物

学习效果以「能否独立写出」为准，不以「看懂」为准：

| 章节 | 应能独立完成 | 验收标准 |
|---|---|---|
| 工程组织 | 静态库 + 动态库各一套 Makefile | `make` 一次通过，`ldd` 能看到依赖 |
| 标准 I/O | 结构体整块存取的用户名密码程序 | 二进制文件可被 `xxd` 读出字段 |
| 系统 I/O | `cp` 命令的四种实现 | 大文件（>100 MB）拷贝不丢字节 |
| 时间 | 每 5 秒建文件，文件名带时间戳 | 连续 10 个文件命名不重复 |
| 目录与属性 | `ls -li` 的完整复刻 | 输出与系统 `ls -li` 逐列对齐 |
| 进程 | `fork` 三次的进程树分析 | 能画出 8 个进程的父子关系图 |
| 信号 | 键盘控制的 MP3 播放器 | 暂停/继续/切歌无残留进程 |
| LVGL | 带时钟与播放控制的界面 | 连续操作 10 分钟不崩、不卡死 |

## （四）环境与约定

- 平台：Ubuntu（图形界面版），编译器 `gcc`，调试 `gdb`，构建 `make`。
- 所有系统调用失败都会设置 `errno`，**必须**用 `perror` 或 `strerror(errno)` 打印，禁止只写 `return -1` 了事。
- 头文件按「系统调用 → 标准库」顺序排列，避免隐式声明告警。
- 代码中的路径一律用 `argv` 传入，不写死绝对路径，否则换机器就废。

> 扩展 · 调试习惯：`strace -f ./a.out` 能看到每一次系统调用的入参与返回值，比在代码里撒 `printf` 高效得多。排查「文件打不开」时，`strace` 会直接告诉你内核返回的是 `EACCES` 还是 `ENOENT`。
